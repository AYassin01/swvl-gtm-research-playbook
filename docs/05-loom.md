# 5. Record the Loom through the guide

Use the repo as your route through real execution. Create the result on a working branch, record the work, add the video link, then merge the completed package. The guide is available on main; the in-progress result is visibly a draft until its artifacts exist.

## Record in stages

1. Open this README/guide in one tab, the real Clay workspace in another, and Codex in your terminal.
2. Start the workflow using the repo prompt. Show the actual hypothesis and price proposal; approve the real X credits on screen if appropriate.
3. Record the important execution steps as they happen: search filters, table creation/population, exact buyer request, returned data and evidence checks. You can pause recording during long waits.
4. Show the actual usage evidence and the report. If charges are unreported, explain that instead of claiming zero.
5. Record a concise three-minute final walkthrough from those real results. Use the generated video-script.md with measured numbers. Keep the task's 60/90/30-second structure.

Do not run paid lookups again just for a retake. Open the completed run and its original references; if you intentionally run a new paid experiment, give it a new run ID and approval.

## Three-minute screen plan

| Time | What to show | What to explain |
| --- | --- | --- |
| 0:00–1:00 | Repo's method page, actual Clay filters/totals and populated table | ICP, size policy, TAM/SAM/SOM, why the list has this size and one exclusion |
| 1:00–2:30 | Codex request/rule, actual buyer results, source check | Five companies/two requests each, three measured totals, right/wrong/unconfirmed, rule-following decision |
| 2:30–3:00 | Tool/credit report and source evidence | Which tools did what, known consumption versus unknowns, one untested point and one next change |

The repo should support your explanation; show real Clay and Codex work, not just static documentation. The full implementation recording may be longer, but the assignment's final summary is approximately three minutes in English.

- Give Codex the actual URL and your access-check confirmation.
- Codex fills the fifth submission item, runs readiness checks, opens/updates the result PR, and merges after checks pass under the workflow you requested.
- Send the repo link; its submission index points to the real workbook, notes, conversation copy and Loom.
