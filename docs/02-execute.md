## Suggested company scope

Industry: outsourced contact-center operators. Place: verified Greater Cairo operating sites. Size: all sizes, no numeric headcount filter. Buyer titles: your adopted family. Offer: managed late-shift employee shuttles with records that help reconcile billed runs.

Existing employer-arranged rides are a separate signal; the company list must not falsely imply every listed business already provides transport. If you explicitly retain that policy as a hard ICP filter, it needs evidence on every included company.

## What an approval looks like

Codex fills the placeholders with supported numbers before asking:

```text
Approve up to X Clay data credits for [specific bounded company/buyer work]
in [workspace], with up to Y search-result units and Z billable Actions
where those units apply. Pricing evidence: [actual source/reference].
This is an estimate/reservation, not an actual charge.
Optional providers: none / separately specified and priced.
```

Do not copy that as a numeric approval while X/Y/Z are unresolved. The approval remains pending until you accept actual numbers. A provider's own approval hold replaces a duplicate question for the same decision.

## If results are sparse

A low buyer yield is a valid measured result. Preserve it and apply the rule. A company shortfall is different: do not pad the table to reach 25. Codex must identify whether scope, data coverage or source evidence caused the gap and propose a clear scope choice. A displayed 25-row page is not a market total.

## Finish with your work, not templates

The owner-specific actions are hypothesis/scope choice, credit approval, exact personal buyer request, authentication when necessary, personal source inspection, recording and access checks. Codex owns supported research, browser table work, calculation, documentation and Git packaging.
